# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## [Unreleased]

### Fixed

- Teamserver: tasking an agent hollowed the event-history entry for that task — the dispatch path deleted every key from the shared `Body.Info` map in place, so reconnecting operators replayed tasks without TaskID/DemonID/CommandLine — and worse, concurrent iteration of that same map during the delete loop crashed the whole teamserver with an unrecoverable `concurrent map iteration and map write` fatal; the dispatch paths now rebind a fresh map instead of mutating the shared one.
- Teamserver: building a payload against a listener configured with both `Headers` and `HostHeader` appended `Host: …` into the live listener's mandatory-header list, where net/http's Host promotion made the check unpassable — every subsequent implant callback was served the fake 404 until teamserver restart (the listener was bricked); the build now works on a copy of the header list.
- Teamserver: `DEMON_PIVOT_SMB_COMMAND` dispatched task output, liveness updates and (given the child's AES key) full forged tasking against any agent named in the inner header, with no binding between the sending implant and the claimed pivot child; pivot traffic is now only accepted from the child's registered pivot parent, and otherwise rejected with an error message.
- Teamserver: the tasked-checkin path adopted an implant-supplied DemonID (and new AES key) with no duplicate check, letting one implant re-identify as another live session and split tasking/output/DB state between the two; a checkin whose DemonID doesn't match the session's registered identity is now rejected.
- Client: `TeamserverTabSession::dbManager` was never assigned, so opening the Script Manager, removing a script or installing any Store extension null-dereferenced and crashed the client; the application-wide database handle is now plumbed into the tab. (Also fixes the `TeamserverName` self-assignment that left the member empty.)
- Client: the `destroyed` handlers of `havocui.widget`/`havocui.logger`/`havocui.tree` nulled only the window pointer, leaving every other struct member dangling after the window was deleted — a script keeping the object across a teamserver disconnect then crashed the client calling `addLabel`/`addText`/`clear`/`setItem`; all members are now nulled when the window dies.
- Teamserver: the payload-builder shell-injection surface (Service Name was fixed earlier) is now closed for the remaining inputs that reach `sh -c`: the Nasm path and the x64/x86 compiler paths from the teamserver settings are validated against a safe character set (and Nasm is quoted), and a failed compiler-path resolution in silent builds now aborts the build instead of running with an empty path.

- Teamserver: an authenticated operator could impersonate another operator in chat, audit trail and task attribution via the client-controlled `Head.User` field; the login username is now derived from `Head.User` (validated against the profile) and `Head.User` is overwritten with the authenticated identity on every subsequent package.
- Teamserver: listeners restored from the database silently lost `KillDate`/`WorkingHours`, so payloads built after a restart embedded no self-termination config; both fields are now restored for HTTP/s and SMB listeners.
- Teamserver: `ListenerEdit` mutated the live HTTP listener config while request goroutines read it (torn slice headers could panic in-flight checkins); the mutable config fields are now swapped under a per-listener RWMutex and request goroutines snapshot them under the read lock.
- Teamserver: `COMMAND_INJECT_DLL`/`COMMAND_SPAWNDLL` responses and `COMMAND_ERROR` (Win32 last-error) reports never completed their tasked requests, pinning the jobs — including full DLL/assembly bytes — in `a.Tasks` forever; all three paths now call `RequestCompleted`.
- Teamserver: pivot children never drained their own job queue, which grew without bound (including queued upload bytes) on SMB-pivot chains; `RequestCompleted` now also drops the matching job from the queue.
- Teamserver: reverse port forward reads buffered the entire remote response until EOF before relaying, exhausting `DEMON_MAX_RESPONSE_LENGTH` on bulk transfers and never relaying a byte on long-lived connections; reads are now streamed in 64KB chunks like the SOCKS path.
- Teamserver: the SOCKS5 greeting and request were parsed through two independent buffered readers, so a pipelined CONNECT request sent with the greeting was silently dropped, and address fields were read with short-read-prone `Read` calls; the handshake now uses one reader per connection and `io.ReadFull`.
- Teamserver: a transient download write error re-created (truncated) the partial file and leaked the old handle, silently corrupting finished downloads; the download is now aborted cleanly (handle closed, state marked stopped).
- Teamserver (Service API): `AgentResponse` was routed by RandID across all service clients, letting any authenticated client answer another client's pending request by guessing the ID; responses are now routed only through the originating client's pending-request channels.
- Teamserver: a profile without an `Operators` block nil-panicked every login attempt via `ListOfUsernames`; the pointer is now nil-guarded.
- Teamserver: one bad listener entry in the profile or database (unparseable KillDate, bad proxy scheme, failed bind) aborted teamserver startup mid-loop with exit status 0, skipping remaining listeners and agent restore; failed listeners are now logged and skipped.
- Teamserver (Service API): websocket writes had no deadline, so a stalled service client could pin the client mutex and queue every subsequent writer indefinitely; all service writes are now bounded by a 10-second deadline.
- Teamserver: FS Explorer directory listings accumulated `DirArr`/`DirMap` entries across directory blocks within one package; the per-block accumulators are now reset per iteration.
- Demon: `pivot smb connect` could block the implant dispatch thread forever waiting on a silent pivot pipe server; the wait is now bounded (~5s, matching the `WaitNamedPipeW` bound) and bails out with a failure response on timeout.
- Demon: `exit` with an unexpected exit method continued into torn-down memory on x86 (wild PC after freeing its own image on x64); any unexpected method now defaults to a safe thread exit.
- Demon: `net sessions` sent the username twice, so the teamserver showed usernames in the Computer column and lost the host; the implant now sends `sesi10_cname` as the computer name (wire format unchanged, teamserver parser untouched).
- Demon: `upload` and `execute-assembly` (inline) never freed their buffered in-memory file copies; `RemoveMemFile` is now called once the upload/assembly execution completes (previously unbounded heap growth and a forensic copy of every upload).
- Demon: the hardware-breakpoint engine leaked a thread handle on every success path (`SetBp` — re-armed twice per AMSI/ETW hit while .NET runs — plus `Add`/`Remove`/`Destroy`); handles are now closed.
- Demon: `CoffeeCleanup` freed the COFF image with a non-zero size under `MEM_RELEASE`, which the API rejects, so the page-granular BOF image leaked on every `coffee` run; size is now 0 as required.
- Demon: reflective DLL injection into a spawned process closed the process handle that was already registered with the jobs list, double-closing the kernel object when the job was later removed.
- Demon: .NET assembly execution treated `CreateNamedPipeW`/`CreateFileW` failures (which return `INVALID_HANDLE_VALUE`) as success, continuing with pseudo-handles; both are now checked properly.
- Demon: `DotnetClose` released the AppDomain thunk and then called `UnloadDomain` with the freed interface (use-after-free), never released `ICorRuntimeHost` (CLR kept loaded) and leaked the assembly `SafeArray`; the teardown order is fixed and the leaks closed.
- Demon: `LdrModulePebByString` allocated a byte-sized `MAX_PATH` buffer but indexed it as wide chars using the `BaseDllName.Length` byte count — out-of-bounds read/write for long module names and no NUL terminator; the buffer is properly sized and NUL-terminated now.
- Demon: `SysInitialize` was declared `BOOL` but never returned a value, so the caller's failure gate tested leftover registers; it now returns whether the syscall address was resolved.
- Demon: `token steal` error paths returned without transmitting a response (the task never completed on the teamserver) and leaked the stolen token handle/buffer; error paths now send a well-formed failure response and free allocations.
- Demon: `FS_DIR` with a failing `GetCurrentDirectoryW` transmitted a truncated packet the teamserver rejects (file browser hangs); a well-formed empty response is sent instead.
- Demon: the task dispatch loop dropped a trailing zero-payload task (`> 12` off-by-one, now `>= 12`), and a zero-payload task reused the previous task's parser buffer; every task now starts from a fresh parser.
- Demon: a download whose `ReadFile` failed was silently removed without notifying the teamserver, leaving the transfer open/incomplete on the operator side; a download-close notification is now sent.
- Demon: Kerberos `purge`/`ptt`/unknown subcommands leaked the duplicated token handle opened by `TokenCurrentHandle`; it is now closed on all paths.
- Demon: transport slow leaks — the registration response buffer in `TransportInit` is now freed after use; on HTTP host rotation a previously discovered proxy structure (and the proxy strings behind it) is freed before re-discovery.
- Demon: `SmbSend` reported success on any pipe-write failure other than `ERROR_NO_DATA` (e.g. `ERROR_BROKEN_PIPE`), so the teamserver discarded queued packages as delivered and task output was silently lost; any write failure now reports failure.
- Demon: a partially-read HTTP response body was marked as a complete successful response (the implant acted on a truncated tasking stream); a failed `WinHttpReadData` mid-body now drops the partial buffer and is treated as a transport failure so the request is retried.
- Teamserver: `LastCallIn` was written as teamserver-local wall time while clients parse it against UTC, so in cross-timezone setups every session showed as hours-stale (or permanently healthy), defeating the sleep-based health indicator; the teamserver now writes `LastCallIn` as UTC (display format unchanged) and the client parses it as UTC.
- Client: removing a session via the table/graph context menu left a ghost entry in the global session list, so a re-registering agent was silently dropped by the duplicate guards until client restart; the Remove path now also erases the session (releasing its queued Python task callbacks) in both the session table and graph menus.
- Client: package decoding dropped non-string `Body.Info` values — the teamserver sends `SleepDelay`/`SleepJitter`/`KillDate`/`WorkingHours` as JSON numbers, so fresh sessions initialized them to 0 and health checks were dead until the first check-in; numbers/bools are now converted to their string form (the wire format is unchanged).
- Client: `Listener.Edit` broadcasts dereferenced the listener table widget without the null check every other listener event has, crashing all connected clients if the table was not created yet; it is guarded now and edits for unknown listeners are ignored.
- Client: the session health "offhours" check was inverted (every normal working-hours window evaluated as off-hours, skipping the healthy/unresponsive check entirely); it now mirrors the Demon's `InWorkingHours` semantics — minutes-of-day comparison, overnight windows wrap correctly, inside the window means active.
- Client: a `config.toml` missing `[scripts]/files` or `[font]` aborted the client with an uncaught `toml::find` exception at login; both are now read defensively with graceful defaults.
- Client: the Process List "Refresh" button compared `Session.Name` against itself (always true), tasking the first session in the list instead of the session the tab belongs to; it now tasks the right agent.
- Client: context menus acted on the wrong row — the session table menu used `currentRow()` (crash when nothing was left-clicked, wrong session otherwise) and popped at the wrong position; the Script Manager menu acted on the last-selected script; the Process List "Copy PID" always read the process tree even when opened on the table, and the tree menu guarded the table's items; the File Browser tree popped the table's Download/Reload menu. All now act on the item under the cursor in the correct widget.
- Client: `createtab` and `Widget/Dialog.addCombobox` fed unchecked `PyTuple_GetItem` results into `PyCallable_Check`/`PyUnicode_AsUTF8` (segfault on the documented `createtab("title", callback)` form or zero-arg calls); arguments are now validated with proper `TypeError`s.
- Client (Python API): `Demon.ProcessCreate` assembled its argument string in the wrong order (state;app;verbose;piped;args) while the teamserver parses state;verbose;piped;app;args — the piped flag became the process path; the order now matches the teamserver parser. The Python-facing signature is unchanged.
- Client: the new-session event iterated `RegisteredCallbacks` by reference while a callback could register another handler and reallocate the vector (use-after-free); iteration now runs over a snapshot.
- Client: third-party agent commands with a `IsFilePath` parameter indexed the argument array before the bounds-checked "required parameter not given" check, reading out of bounds when fewer arguments were supplied than declared; the index is now bounds-checked first.
- Client: `inline-execute` dropped the first BOF argument (the join started at token 3 while the function name `go` is hardcoded, so arguments start at token 2 — the command's own documented example tasked the BOF with no arguments).
- Client: `config implant.sleep-mask` was a standalone `if` ahead of the config `else if` chain, so the chain's final `else` reported "Config does not exist" before sending — the setting could never be applied; the chain is now contiguous.
- Client: `shellcode spawn`/`execute` continued tasking after an invalid architecture error (unlike `shellcode inject`); they now return after the error.
- Teamserver: service-registered listeners were appended to the listener list even when their `Start` failed and without a duplicate-name check, so dead entries accumulated and could shadow the payload-build listener lookup; failed listeners are no longer registered and duplicate names are rejected.
- Teamserver: adding an SMB pivot listener without a `PipeName` cleared the listener's `Name` instead of leaving the pipe name empty (copy-paste); the correct field is cleared now.
- Teamserver: external-C2 endpoint routing matched the raw `RequestURI` including any query string, so third-party agents appending query parameters to the callback URL never matched their endpoint; matching now uses the URL path only.
- Teamserver: a registration with header AgentID `0` adopted the attacker-chosen embedded DemonID with no duplicate check, allowing a second in-memory session with an existing session's NameID; DemonID `0` and registrations colliding with an existing session are now rejected.
- Teamserver: the agent/listener database insert helpers leaked their prepared statements on `Exec` error paths; the statements are now closed on those paths.
- Teamserver: `AddJobToQueue` returned the job queue read outside the agent mutex (callers discard the value; race-detector noise); it no longer returns anything.
- Teamserver: `socks add` on a port whose asynchronous bind failed left the dead server listed by `socks list`; a failed bind now removes the entry and logs the error.
- Teamserver (Service API): `HeadRegisterAgent`'s agent-name duplicate check-then-append ran outside the state mutex, so two racing clients could both register the same name; the check and append are now atomic.
- Teamserver: residual `rand.Seed(time.Now().UnixNano())` on the global math/rand source (pipe-template pick and `GeneratePipeName`/`GetRandomChar`, whose output feeds SMB pipe names) replaced with crypto/rand; concurrent global-rand consumers no longer correlate.
- Teamserver: certificate generation called `logger.Fatal` (os.Exit) on a signing failure, killing the whole teamserver; it now logs the error and propagates it to the caller.
- Teamserver: the CLI banner reported the stale version string `0.7.2`; it now matches the release version (`0.8.2`, same as the client).

## [0.8.2] - 2026-08-28

### Fixed

- Teamserver: the `agent.command` Encryption scrub for service agents used an invalid type assertion on a concrete map — the teamserver did not compile; the scrub now deletes the key directly.
- Teamserver: the HTTP listener bound its port inside the serve goroutine, so a failed bind (port in use) was only discovered after the listener had been registered as online; `Start()` now validates the TLS certificate pair and binds synchronously — a failed bind or bad cert is reported and the listener is not registered — which also removes the race where `Stop()` read `h.Server` while the serve goroutine wrote it, and the window where `Stop()` right after `Start()` wrongly reported the listener as not running. The dead post-shutdown `select` in `Stop()` (which always blocked the full 5-second timeout) is gone.
- Teamserver: the operator client's `ClientID`/`Username` were assigned after releasing the client mutex on successful login, so a concurrent disconnect in that window broadcast `UserDisconnected("")`; both are now assigned inside the locked block.
- Teamserver: `RemoveClient` used check-then-delete on the client registry, so the panic watchdog and the read-loop error path could both pass the check for the same client and broadcast `UserDisconnected` twice; it now atomically `LoadAndDelete`s.
- Client: the pivot-graph reconnect path declared a `GraphNode*` — a type that does not exist — so the client did not compile; it now uses the `Node*` that `GraphNodeGet` returns.
- Client: the Python module-command paths set a `TypeError` on the interpreter and then released the GIL without clearing it, leaving a pending exception that leaked into unrelated C-API calls; both sites now report a console task error instead of raising.
- Client: the `help` listing branch tested `SubCommands.empty()` and then indexed `SubCommands[0]` (undefined behavior on the empty path); the guard is inverted to `!empty()` as intended.
- Client: the `createtab` menu-action callback invoked Python without printing/clearing exceptions raised by a failing callable; it now print-and-clears like every other callback site.
- Client: the seven `havocui.dialog` callbacks (button, checkbox, combobox, line edit, calendar, dial, slider) held owned references that were never released; each is now decref'd when its widget is destroyed. The same leak existed in all seven `havocui.widget` callbacks and is fixed the same way.
- Client: on teamserver disconnect the queued per-task Python callbacks (`TaskIDToPythonCallbacks`) were dropped without decref, leaking the referenced callables; they are released (under the GIL) before the session list is cleared.
- Client: `tree.setPanel` HTML-escaped its input before `setHtml`, so scripts passing intentional markup got it rendered literally; the markup is rendered as-is again (matching the original behavior — note this is a behavior change for scripts that relied on the escaped rendering).
- Client: `NewBottomTab`/`NewSmallTab` crashed the client when a script called them with no teamserver session; they now report failure to the caller and the Python wrappers (`setBottomTab`/`setSmallTab` on widget, logger and tree) raise `RuntimeError` instead of silently succeeding or dropping the widget.
- Client: re-registering a Python command with the same callable decref'd the old reference before incref'ing the new one, which could free the object mid-swap; the order is now incref-first.
- Demon: the SMB pivot read loop leaked the output buffer on every failure after allocation (`ReadFile` failure, pivot-data and pipe-name allocation failures); all failure paths now free it.
- Demon: the five `PackageAdd*` builders assigned `LocalReAlloc` directly into `Package->Buffer`, so an OOM failure overwrote the old pointer (leak) and left later `PackageAdd*`/`PackageTransmit` operating on a NULL buffer with a stale length; they now realloc through a temp variable like `AnonPipesRead`.
- Demon: the HTTP response reader had the same direct-`LocalReAlloc` pattern in its download loop; it now reallocs through a temp so a failure cannot leak the accumulated response.
- Demon: `ProcessCreate` copied a wide command line using its character count as a byte count — half the string was copied and the zeroing freed with the same wrong size; both now use `x * sizeof(WCHAR)`.
- Demon: the .NET assembly runner advanced the `CommandLineToArgvW` result pointer past `argv[0]`, losing the allocation base so it could never be freed; the base pointer is saved and released as soon as the argument strings have been copied into the safe array (including the failure paths in between).

## [0.8.1] - 2026-08-28

### Fixed

- Teamserver: agent session JSON (ToMap) embedded live `*Agent` pointers for pivot links, handing marshal-time consumers mutable shared state that could crash under concurrent pivot connect/disconnect; the map now carries pivot child NameIDs under `PivotLinks` (and `PivotParent` as before) instead of pointers.
- Teamserver: the Service API `SendResponse` path returned full agent data — including the agent's AES key/IV — for any magic value match, and to service agents whose registered magic differed from the requesting agent's; the handler now only returns agent data when the magic values match and strips the `Encryption` block from the response.
- Teamserver: a truncated or mistyped pivot job entry in a task batch (missing `Data[1]`/`Data[2]`, wrong types) panicked the request handler and dropped the whole batch; the pivot drain now validates lengths and types and skips malformed entries.
- Teamserver: `SendEvent` wrote operator events without a deadline, so one stalled websocket client blocked event broadcasts (and everything serialized behind the client mutex) indefinitely; writes are now bounded and stalled clients are dropped.
- Teamserver: a panic inside the service-client dispatch loop skipped connection/agent teardown; the client is now cleaned up via `defer` once authenticated.
- Teamserver: task preparation and the listener/payload handlers indexed operator-controlled maps and split arrays unchecked (missing `Binary`/`PID`/`Arguments`/`CommandID` fields, `dir`/`upload`/`proc create`/`token`/`config` argument strings with too few or too many parts), panicking the teamserver on malformed tasking; all fields are now type-checked and argument splits length-checked, degrading to a task error instead.
- Teamserver: login paths that rejected a client before authentication (unknown username, duplicate username, malformed auth packet) removed the client without closing its connection, leaking the socket/file descriptor per attempt — a pre-auth DoS vector; all rejection paths now close the connection like the throttled/bad-password branches already did.
- Teamserver: a dying agent's pivot links were read unlocked (`Pivots.Links[0]`) while request handlers mutate them; `UnlinkFromAll` now iterates a locked snapshot. A deregistering service agent between the existence check and the `SendResponse` call could also nil-panic the request handler; the interface is nil-checked. `Service.ClientClose` no longer broadcasts mark-as-dead events while holding the service state mutex (potential deadlock against handlers it wakes), and the agent-restore path uses the locked `PivotParentSet` accessor instead of writing `Pivots.Parent` directly.
- Teamserver: the http-listener startup-failure error message now reports the configured listener name instead of a possibly stale variable.
- Teamserver: websocket clients that had not completed the operator login handshake still received every broadcast event — including new-session packages carrying the agent AES key/IV, all agent console output, screenshots, downloads, operator chat and listener events. Broadcasts now skip unauthenticated clients, and connections that never send a login packet are dropped after 30 seconds.
- Teamserver: a payload-build request whose JSON config lacked the `Injection` object (or had it as the wrong type) crashed the whole teamserver through an unchecked type assertion inside an unrecovered goroutine; the assertion is comma-ok checked and the build goroutine now recovers panics, reports the failure to the operator and still cleans up the temp build directory.
- Teamserver: odd-length UTF-16 strings from an implant (process names, directory listings, token lists, …) read one byte past the buffer end and panicked the request handler; the decoder now stops at the last complete code unit.
- Teamserver: any request whose header parsed with a non-Demon magic value panicked the handler when the profile had no Service block (`t.Service` is nil); the service-agent lookup now returns false in that case.
- Teamserver: a malformed nested register packet inside a `DEMON_PIVOT_SMB_CONNECT` response nil-dereferenced the handler; parse failures now surface as a normal connect-failure message. The same lookup races between `AgentExist` and `AgentInstance` in the implant request handlers are closed.
- Teamserver: an agent dying with two or more SMB pivot links panicked `UnlinkFromAll` (index out of range) because the loop shrank the slice it was ranging over; the rewrite removes links head-first.
- Teamserver: an `fs dir` response with an empty `RootDirPath` panicked slicing `s[:-1]`; empty paths now degrade to the bare file name.
- Teamserver: the Service API endpoint had no login rate limiting (one password guess per connection, unlimited reconnects) and its client/agent/listener registries were read and mutated from concurrent goroutines without synchronization; logins are now throttled per source IP (5 failures → 5-minute lockout, the same policy as operator logins) and the registries are guarded by an RWMutex with snapshot accessors for iterating code.
- Teamserver: profiles without a `Demon` block (service-only teamserver setups) nil-panicked the teamserver on profile send, listener creation/update, payload build and `GetDotNetPipeTemplate`; all `Config.Demon` accesses are now nil-guarded and degrade to sane defaults.
- Teamserver: the service-endpoint registry (`t.Endpoints`) was read by the gin route handler while service agents add/remove endpoints at runtime; it is now guarded by an RWMutex (the route handler copies the callback out and invokes it outside the lock).
- Teamserver: pivot link/parent bookkeeping (`Pivots.Links`, `Pivots.Parent`, `LastCallIn`) was mutated from concurrent request-handler goroutines without synchronization, which could crash while iterating or slice a concurrently-mutated list; all mutation now goes through per-agent-locked helpers, and iteration copies the list under the lock.
- Teamserver: a `sleep` task whose argument string lacked the `;` separator panicked on `ArgArray[1]`; sleep tasks now also validate that the delay is non-negative and the jitter is 0–100 before tasking the implant.
- Teamserver: the endpoint dispatch loop unlocked the endpoint mutex around handler execution but kept indexing the live endpoint slice — a concurrent endpoint removal shrank the slice mid-iteration and panicked out of range, and a panicking handler left the lock discipline broken; the matching handlers are now snapshotted under the read lock and executed without it.
- Teamserver: the pre-auth websocket read deadline was cleared only after `SendAllPackagesToNewClient`, so a large event-history sync could eat the whole 30-second budget and disconnect a freshly authenticated operator on its next read; the deadline is now lifted immediately after authentication succeeds.
- Teamserver: the operator client's `Authenticated` flag was written on login and read from the unauthenticated-drop watchdog, broadcast filter and disconnect cleanup without any synchronization (only the service-client equivalent was guarded); all reads and writes now take the client's own mutex, mirroring `ClientService`.
- Teamserver: the SMB pivot reconnect path wrote `Active`/`Reason` without the agent mutex while `ToMap` reads them under lock; the writes are now guarded.
- Teamserver: the `agent.command` dispatch to service agents still sent the full agent `ToMap()` — including the agent's AES key/IV — even though the request-handler path strips the `Encryption` block; the same scrub now applies to the service-agent task path.
- Teamserver: the HTTP listener's `Active` flag is set/cleared from the serve goroutine and read by listener management without synchronization; it is now an `atomic.Bool`. (An async bind failure still only surfaces after the listener is registered — the flag fix does not change that.)
- Client: removing a session from the graph view erased the list entry before using it (`removeChild` on the wrong index) and leaked the node/edge objects; the context-menu Remove routed through a full teardown that detaches the node from its parent, children and every edge referencing it.
- Client: the reconnect teardown nulled `TabSession` but left `Teamserver.Sessions` populated with entries referencing the destroyed tab's widgets; sessions are cleared with the tab.
- Client: `help` padding computed `TotalSize - name.size()` in unsigned arithmetic, so any registered module/command name longer than the column crashed the console; all padding sites are clamped (this also covers the fixed-width variant fixed earlier for service-registered commands).
- Client: `proc create` with `--silent` as the last argument read past the end of the argument list (`--no-pipe` and the program path likewise); the parser now bounds-checks every index.
- Client: `PathGetParent` in the file browser started its reverse scan one past the end of the string and underflowed on paths without a separator; it is now bounded and returns an empty path instead.
- Client: Python `ConsoleWrite` output and the teamserver log view accepted script/operator-controlled text unescaped into rich-text widgets; the message buffers are now HTML-escaped at the sink.
- Client: `NewBottomTab`/`NewSmallTab` dereferenced `TabSession` unconditionally, so a script touching the UI after a disconnect (or before the first connect) crashed; they now no-op without an active session.
- Client: inline Python module commands returned a non-string value were passed to `PyUnicode_AsUTF8` unchecked at one of the three call sites (crash); the missing type check is added, and the ~25 `PyArg_ParseTuple` failure paths that returned `None` (with a pending exception) now properly return `NULL`.
- Client: the `havocui.tree` selection-changed callback captured the Python object raw, so deallocating the tree while the Qt widget still fired the signal was a use-after-free crash; the callback now holds an owned reference to the object and releases it when the window is destroyed.
- Client: Python dialogs (`havocui.dialog`) were leaked — the deallocator's parent check could never match since dialogs are always parented to the main window; they are now deleted unconditionally on dealloc.
- Client: the Extensions Store `dataStore` pointer was uninitialized until the first successful fetch; it now defaults to null, and the table row counter is kept separate from the store-index mapping so non-object JSON entries cannot desync which entry gets installed/displayed.
- Client: malformed service-agent JSON (missing listener `Name`, malformed custom-listener definitions) could throw nlohmann exceptions past the guarded parse and abort the dispatch/UI; the post-parse accesses are now guarded. `agent.command` with a non-bytes argument and `tree.addRow` error paths now return a proper Python exception instead of `None` with an exception set, and the plugin-command paths no longer leak the argument tuple on the no-send and non-callable branches.
- Client: the client crashed about a second after any disconnect — the one-second session-health timer kept dereferencing the torn-down teamserver tab (`TabSession`, nulled by the reconnect flow) while the session list survived until the next successful connect. `UpdateSessionsHealth`, `MarkSessionAs` and the mark-as package send now null-check the connection state.
- Client: agent-controlled `MiscData2`/`MiscData` output without the expected `;` separator crashed the operator client with an out-of-bounds `QStringList` access (download notifications and pivot-graph reconnect events); malformed fields are now ignored.
- Client: `havoc.Event.OnNewSession` and the Gate payload callback stored borrowed Python references; once the registering script's callable was garbage-collected, the next matching network event called freed objects (use-after-free). Both now own their reference, and the Gate dispatch prints-and-clears exceptions raised by failing callbacks.
- Client: the borrowed-reference/no-GIL callback pattern fixed for `createtab`/`progressdialog` also existed in about a dozen more UI callbacks (buttons, checkboxes, comboboxes, line edits, calendars, dials, sliders in the Widget/Dialog Python classes and the tree selection handler); all now `Py_INCREF` the callable, call it under the GIL, dispose their argument/result objects and print-and-clear raised exceptions. The Widget/Dialog/Tree/Logger deallocators no longer `Py_DECREF` malloc'd title buffers (heap corruption on every destruction) and no longer double-delete Qt-reparented windows.
- Client: the Extensions Store built download and clone paths from store-index-controlled names, so an index entry with `entrypoint = ../../evil.py` could write — and then load as a script — a file outside `data/extensions`; names containing path separators or `..` are rejected, and a failed download no longer falls back to loading whatever stale file already sits at the target path.

### Changed

- The per-agent SOCKS5 proxy now binds to `127.0.0.1` only instead of `0.0.0.0` (it was an unauthenticated open relay). Use port forwarding if remote access to the proxy port is needed. (#45)
